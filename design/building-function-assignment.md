# 建築・タイル機能割り当て

建築・タイルアイコン案に含まれる46項目（基礎1、床材8、建築物37）のシステム上の役割を整理する。アイコン案の説明文は機能確定を意味しない。ゲーム機能の実装状況と将来案を分けて扱う。

## 状態の見方

- **実装**: 現在のゲームで、記載した機能が操作・処理として動く。
- **一部**: データや製作設備などの基礎だけが動き、説明にある本来の設備機能は未完成。
- **案**: 機能の提案。現在のゲーム動作として扱わない。

## 共通ルール

- 建築キットの作成時に真鍮を消費し、所持品から設置するときはキットを1個消費する。キット設置では真鍮を再消費しない。
- 幅・高さがともに2セル以上の建築キットは、作業台・歯車生成炉、または生産以降の建築設備が置かれると作成可能になる。
- 9セル以上を占有する構造物は、占有範囲すべてに基礎セルが必要。現在の基礎セルはこの配置条件を担う。
- 製作設備とレシピの対応は `MapSystem/js/craftingData.js` の `CRAFTING_STATION_BUILDING_IDS` を唯一の定義元とする。対応設備の存在確認、レシピ表示、製作開始時の設備確認はゲーム側に実装済み。
- 床材の効果を建築物の詳細へ集める処理はあるが、現在の床材データに効果は定義されていない。排水、耐熱、通行、配管接続などの効果は未実装。
- 水・蒸気は局所ネットワークで移送・貯留され、設備メニューに接続量、容量、蒸気圧力指標、ボイラー不足状態を表示する。GearSystemのグローバル資源とは分離している。水質、霧・環境状態、採掘機、自動作業者、飛空艇の物流は未実装。人口・住民数はゲームシステムに含めない。
- 新天地テラフォーミングドームは最終目標。気候制御核・閉鎖循環ユニット・生態系スターターの3加工品に加え、深部ドリル、地熱コレクター、中央タービン、遺物解読炉、階差演算タワー、浄化タワー、生態系試験棟、テラフォーミング管制棟の配置を建設条件とする。各設備の稼働状態やネットワーク接続状態は現段階では条件にしない。

## 水・蒸気の流量と圧力ルール

- 水と蒸気は別資源のネットワークとして扱う。接続成分は、辺で接した建物間の同種ポート接続から導出し、角接触・資源種の不一致・入力同士・出力同士は接続しない。
- 配管専用建築を追加するまでは、互換ポートを持つ建物の footprint が辺で直接接している場合だけ接続する。各ポートは footprint の全辺で有効とし、接続方向の回転設定は持たない。
- 資源量は局所設備ネットワーク内で扱い、GearSystem のグローバル `water` / `steamPower` とは別会計にする。既存のギア資源を自動で供給・消費しない。
- 生産量・要求量は連続量、処理速度は毎秒量とし、シミュレーションの実経過時間を掛けて加減する。フレーム数に比例した固定加算はしない。
- 1回の更新では、稼働可能な供給元から生産を見積もり、保存済み在庫と合わせた共有供給量を作る。その後、消費側を安定した建築 `instanceId` 順に処理し、要求量・設備速度・残量の最小値だけを割り当てる。同じ資源を複数の枝へ複製しない。
- 消費後の余剰だけを接続ネットワーク内の蓄圧器・貯水槽へ保存容量まで配分する。容量超過分は保持しない。供給元・消費先が同じ更新内で直結している場合は、バッファ容量がなくても供給分を消費できる。
- 圧力は蒸気ネットワーク内の蓄圧器に保存された量と合計容量から求める0〜100の表示指標とし、独立した資源や物理単位とは扱わない。合計容量が0なら「圧力なし」とし、圧力計は接続中の蒸気ネットワークだけを表示する。
- 不足時は処理を不足分だけ進めるか停止し、未供給量を他資源・他ネットワークから補わない。具体的な生産速度、消費速度、貯留容量、最低圧力は設備別パラメーターで定義する。
- この流量・貯留・圧力指標のv1は実装済み。局所状態は設備インスタンスへ保存し、旧建築セーブは空の状態へ移行する。設備メニューは現在量・容量・圧力とボイラーの水不足、石炭不足、蓄圧器満杯を表示する。

## 初期設備数値（v1案）

水・蒸気の量は連続したネットワーク単位、流量はネットワーク単位/秒で表す。以下は最初の動作確認用の基準値で、後から設備バランスとして調整できる。

| 建築物 | 初期値 | 動作条件 |
| --- | --- | --- |
| 手回し式揚管ポンプ | 水を1単位/秒出力 | 隣接するマップセルが `SEA` または `LAKE`。水・蒸気のギア資源を消費しない。 |
| 霧水貯蔵槽 | 水を100単位貯留 | 接続した水ネットワークの余剰を受け入れ、供給不足時に払い出す。 |
| 蒸気ボイラー＆鍛造炉 | 水1単位/秒と石炭0.1個/秒を消費し、蒸気1単位/秒を出力 | 水ネットワークと蒸気ネットワークの両方に接続し、石炭在庫がある間だけ稼働。水・石炭どちらか不足なら両方を消費せず停止。 |
| 蒸気蓄圧器 | 蒸気を100単位貯留 | 接続した蒸気ネットワークの余剰を受け入れ、供給不足時に払い出す。 |
| 圧力計ペデスタル塔 | 資源消費なし | 蒸気蓄圧器の合計容量がある接続網だけ圧力指標を表示する。 |
| 蒸気炉塔 | 貯留なし・消費なし | 接続網を延ばす中継設備。流量制限や圧力増幅はv1に含めない。 |

v1の圧力指標は `floor(100 * 保存蒸気量 / 接続蓄圧器の合計容量)` を0〜100へ制限した割合表示とする。これはGearSystemの `steamPower` とは独立したローカル値で、物理単位の圧力ではない。水質、濾過、霧低減、噴水での補給、発電、地熱出力は対応する品質・プレイヤー状態・動力網・地熱セルがないため、v1では流量を発生させない。

## 実装の順序

1. 現行の製作設備とレシピ対応を維持し、各設備の製作内容をこの資料とゲームデータで照合する。
2. 水・蒸気の局所接続、移送、貯留、圧力表示、旧セーブ移行は実装済み。
3. 水質と濾過、噴水の利用、霧よけベントの環境効果を、それぞれの品質・プレイヤー状態・環境状態が定義された後に接続する。
4. タービンの機械動力出力と地熱コレクターは、局所動力網と地熱セルを定義してから実装する。
5. 選鉱・掘削・貨物施設は、資源地点・在庫移送・輸送の共通仕様に接続する。
6. 自動化、飛行、環境改変、移動都市は、それぞれの状態モデルとセーブ互換性を定義した後に実装する。人口・住民数は対象外とする。

この資料は設計上の整理であり、**「案」「一部」とした機能がゲーム内で動作することを意味しない**。
